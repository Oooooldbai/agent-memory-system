# 🔥 消防队模式 - 多Agent任务分配架构

> 解决子Agent状态不明、运行缓慢、反馈循环问题

---

## 核心思想

| 角色 | 类比 | 职责 | 生命周期 |
|------|------|------|---------|
| **女娲** | 消防指挥官 | 任务拆解、监控总进度、异常处理 | 长期 |
| **盘古** | 调度中心 | 生成子任务、触发子Agent、不等待 | 单次 |
| **子Agent** | 消防员 | 拿任务→执行→写结果→立即退出 | 短时(<5分钟) |

**关键原则：**
- 子Agent = 一次性，做完立即退出
- 主Agent = 不阻塞，异步验收
- 检查点 = 文件系统，所有人可见

## 执行规范

### 1. 任务拆解原则

**批大小：100条/批次**
- 原因：API限制 + 执行时间<5分钟
- 每批独立文件：`batch{X}_{district}_part{Y}.jsonl`

### 2. 子Agent执行流程（严格5步）

```
1. 读取任务参数（batch_id, doc_token, range）
2. 读取文档内容（API调用）
3. 提取结构化数据（100条）
4. 写入文件 + 标记检查点
5. 立即退出（不汇报，不写总结）
```

**禁止行为：**
- ❌ 不要等待其他子agent
- ❌ 不要汇报"我正在处理"
- ❌ 不要轮询检查状态
- ❌ 不要长时间运行（>5分钟）

### 3. 盘古（Dispatcher）执行流程

```
1. 女娲给出任务："处理Batch 4-8"
2. 盘古拆解：Batch 4 → 4个子任务（每批100条）
3. 盘古并行触发子agent（不等待）
4. 盘古立即返回："已触发4个子任务"
5. 女娲通过检查点文件监控进度
```

**禁止行为：**
- ❌ 不要等子agent完成再返回
- ❌ 不要轮询检查子agent状态
- ❌ 不要让子agent运行太久

## 对比：旧模式 vs 消防队模式

| 维度 | 旧模式（有问题） | 消防队模式（优化） |
|------|----------------|------------------|
| 子Agent生命周期 | 长（等待所有完成） | 短（<5分钟，立即退出） |
| 主Agent状态 | 阻塞等待 | 异步触发，立即返回 |
| 进度监控 | 轮询检查 | 检查点文件 |
| 故障恢复 | 难（状态不明） | 易（检查点可恢复） |
| 并行度 | 低（串行等待） | 高（并行触发） |
